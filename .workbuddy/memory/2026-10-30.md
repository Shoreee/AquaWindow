## `scripts/dev.mjs` 在 Windows 上无法启动（已还原，未采用修复）

原脚本 `pnpm dev` 直接崩 `Error: kill EINVAL`，且修好崩溃后 Vite 仍静默不启动。三个叠加的 Windows 问题：

1. `spawn("pnpm", ...)` 找不到可执行文件（pnpm 实际是 `pnpm.cmd`），child 触发 `error` → `stop()` 对未启动的进程
   调 `kill("SIGTERM")` → 未捕获的 EINVAL。
2. 两个 `pnpm exec` 并发时，第二个会挂住且完全无输出（单独跑都正常）。
3. 两个子进程 `stdio: "inherit"` 共享同一个 stdout 句柄时，当 stdout 是管道（非终端），第二个进程会卡死。

当时写出的可行修复（`process.execPath` 直跑 `node_modules/tsx/dist/cli.mjs` 与 `node_modules/vite/bin/vite.js`，
每个 child 独立 `pipe` 再转发，`stop()` 跳过无 pid 的 child）**已验证可用，但用户要求不修改任何文件，已 `git checkout` 还原**。
若以后需要修复，按上述三点改 `scripts/dev.mjs` 即可。

## 当前采用的零改动启动方式

`pnpm dev` 是坏的，因此分两个终端各起一个进程（不动任何文件）：
```bash
pnpm exec tsx watch server/index.ts                      # Agent 服务 8787
pnpm exec vite --host 127.0.0.1 --port 5173              # Vite 5173
```
注意 `--host 127.0.0.1`：不加则只绑 IPv6 `[::1]:5173`，`127.0.0.1` 连不上。

## 访问地址

- 开发页面：http://localhost:5173/ （`127.0.0.1:5173` 在加了 `--host 127.0.0.1` 后同样可用）
- Agent API：http://127.0.0.1:8787（直接访问 / 返回 404 属正常，只提供 /api 路由）
