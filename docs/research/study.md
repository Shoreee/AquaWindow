# 怎么用这套桌面做对照

## 条件

菜单 **Study** 里有四个预设，写进每条日志：

| 条件 | 技术 | Agent |
| --- | --- | --- |
| baseline | 普通圆角矩形，重叠 | 关 |
| tiling | 加上贴边 | 关 |
| fluid | 超椭圆、退让、掀角、深度、融合 | 关 |
| fluid-agent | fluid，再加语义文件、来源、幽灵层 | 开 |

场景里的方案 A/B/C… 比这四个预设更细：它们只改该问题需要对照的那几项。加载方案时会记下 `scenario` 和 `strategy`。

## 一次 session

1. 打开研究台（`` ` ``），填参与者编号。
2. 用控制台里的矩阵，或 **Scenario** 菜单，启动「场景 × 方案」。计时从这一刻开始。
3. 把任务读给被试（卡片上的 Task / Goal）。不要提示解法；卡片下半的 “try this” 是给研究者自己看的。
4. 自主度默认是 Preview。若该方案要看 Auto+Undo，让被试自己拨右上角的旋钮，这样「谁打开了自动」留在日志里。
5. 结束时导出 JSONL。

目标达成时桌面底部会 toast，日志里有一条 `study / goal`，带从开场算起的秒数。例如：找到那篇论文、把两个数字写进草稿、在被点名后点下 Unmute、导出教程里的 PNG、画满 20 笔。

## 日志里有什么

每行一个 JSON。公共字段：`t`（页面性能时间）、`wall`、`src`、`type`、`condition`、`scenario`、`strategy`、`participant`。

| src | 用来看 |
| --- | --- |
| kernel | 打开、聚焦、移动、缩放、最小化、深度、撤销。拖拽每 250ms 最多一条 |
| bus | 应用自己的语义事件：搜索没命中、wiki 跳转、教程步骤、点名、agent 写了文件 |
| agent | 提案、接受、部分接受、拒绝、自动应用。带规则 id 和置信度 |
| technique | 掀角、融合、深度滚轮 |
| study | 场景开始、目标达成 |

研究台的 Session 页把聚焦次数、移动次数、提案的接受/拒绝、撤销、掀角和深度操作做成计数。Agent 页是每条规则的累计和最近决定。

## 建议的对照，而不是唯一的实验设计

- **RQ1。** 场景 2 的 D（退让）对 E（缩放），同一篇论文压在同一段草稿上。看完成抄录的时间，以及表格在被挡住期间是否仍可读。场景 4 的 C 对 A 看同样的事：视频和软件互相挤压时，人是在看变形的视频，还是在不停改大小。
- **RQ2。** 场景 5 打开 Layout Lab，先看 math 与 human 的 strangeness，再决定是否把其中一个预览到桌面上。场景 1 的 A 对 D：没有语义时搜索 “foveated” 是空的；agent 提议打开透镜之后，同一条搜索命中标题。记录接受前的等待和拒绝后的再提案（置信度应下降，且 12 秒内不重复同一条具体提案）。
- **RQ3。** 场景 2 的深度轨迹：连续打开五页之后，用 `⌥` 滚轮往回走，对照方案 A 的标签。场景 3 的 D：把会议推进深度后按住空格，对照最小化到 Dock 再点回来。

场景卡片会在大约 8 秒后收成左下角的小条，避免挡住要操作的控件。点小条可以展开。鼠标停在卡片上时不会自动收起。
