# 动画更新开销

窗口外壳逐帧移动，应用文档树按真实内容变更更新。`sameAppContent` 只忽略动作、队列、边沿和揭示等表现元数据；文件查询、分组、论文切换、文档编辑、窗口身份仍会触发内容更新。分生中的原文层通过独立的 `AppSurface` 保留，内容透明度在轻量外层变化。

标题栏和缩放命中区缓存其结构，事件通过 ref 读取最新拖动、缩放逻辑，避免缓存旧位置。菜单栏、Dock、原子核心的 React 提示树、图标、关闭的窗口总览和切换器不再被每个布局帧重建。能量与流体几何仍使用原来的逐帧时钟。

已用矢量轮廓裁切和合成层内容形变替换整窗 SVG 噪声、模糊、合成和像素位移图；动态阶段不再对 SourceGraphic 执行逐像素滤镜。原窗口材质在同一轮廓下延伸，波动继续越过角落；裂合时的低频内容形变由合成层上的二维变换完成。窗口动画期间去掉不透明标题填充下重复的背景模糊。反馈样式去重并对不可见的小数抖动取整，空闲鼠标不再读取所有窗口几何；`adaptation.preview` 的研究日志按 250ms 采样，内核状态与动作时钟继续逐帧更新。

同机隔离压测使用 Chrome headless、1920×1080、DPR 2、4 倍 CPU 限速和 Vite 开发模式，完整运行三组本地方案。动作阶段超过 25ms 的帧占比从 324/966（33.5%）降到 23/1296（1.8%），分生平均帧间隔从 29.6ms 降到 17.8ms；脚本耗时从 14.23s 降到 8.13s。该数据是压力测试结果，不是对所有设备实际刷新率的保证。原始摘要见 [测量数据](animation-performance-2026-10-29.json)。

`pnpm test:render` 直接计数浏览器中的应用渲染：移动与揭示期间论文和笔记树均不重绘，实际切换论文后必须立即更新。另运行 `pnpm test`、`pnpm test:fluid`、`pnpm test:embodied` 和 `pnpm test:e2e` 验证布局、回收、裂合、会话恢复与编辑交互。

## 实际显示的合成层回归

上一轮开发模式限速测试验证的是脚本和 rAF 回调，不能据此判断显示器最终呈现是否流畅。有界面的 Chrome 追踪进一步复现了整窗 SVG 位移滤镜的绘制瓶颈，因此已经移除该渲染路径，而不是仅缓存其 React 节点。

同一台机器、1600×950、DPR 2、无 CPU 限速，固定 3.1 秒的分生形变片段中，Chrome `MainFrame.Draw` 事件的单次平均耗时从 10.34ms 降到 0.32ms，峰值从 18.64ms 降到 2.50ms；追踪到的 `DroppedFrame` 事件由 264 降到 21。这些是追踪作用域与事件计数，不等同于整帧端到端耗时或通用掉帧率。数据见 [合成层测量](compositor-performance-2026-10-29.json)。

浏览器回归要求形变期间存在原生窗口轮廓裁切，窗口内不允许重新出现 `feDisplacementMap`。鼠标核心与光带仍由原 WebGL 渲染器绘制。

复测命令：启动开发服务后运行 `pnpm test:compositor`，它会打开独立的可见 Chrome 窗口，记录相同的 3.1 秒形变片段，输出绘制事件摘要，并把完整追踪保存到 `screenshots/qa/compositor-trace.json`。该命令不访问模型服务。
