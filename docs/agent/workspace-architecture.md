# Agent 工作区模型与快速反馈

实施日期：2026-11-03。本文区分已实现能力、工程参数和留待实验/确认的能力。

## 授权范围

- 当前模拟桌面；应用观察与窗口操作接口可扩展。
- 仅组织现有窗口，后台不执行布局；长按选窗、方向键浏览、松开采用、Esc 撤回保持原手势。
- 不生成新信息视图或改写文档；新技术须先确认。
- 本轮不改实验设计，不添加 Agent 验证实验的研究打点。
- 实验研究 why：哪些任务条件解释交互技术的收益、代价与适用边界；不实施 2×2 系统有效性实验，不按固定人数/时长缩减设计。

## 本地模型与 token 边界

TaskDrivenWorkspace 持续保留对象指纹、状态版本、语义版本、明确的同文档/打开来源关系。应用通过 observeApp 发布已观察内容，避免每次请求从全桌面提取上下文。当前接入可见 PDF 页的真实文本、页码和滚动位置、笔记内容、实际文件列表、图库条目、浏览器查询/可读取页面以及对话内容。无法读取的外部页面或图片只提供元数据，空图库明确为空；不读取实验正确答案、题号对应意图或评分。

默认相关对象投影至四窗；显式选择可增加到现有协议的八窗上限。相关对象来源依次为显式选择/当前对象、已知关系、近期操作和当前窗口；这是有边界的检索策略，不能宣称已准确识别任务。文档身份和 openedFrom 是事实，任务解释始终是 tentative，且须引用真实 sourceIds。来源变化后旧解释不进入当前请求。

首次请求发送完整但紧凑的工作区模型；提供方返回后分配不可猜测的 referenceId，客户端缓存真实模型结果和对应 wireContext。后续请求发送 baseId＋delta，仅包含变化的全局字段、窗口和来源，以及移除/排序信息。共享 planningIO.ts 在本地服务和访客密钥直连路径中使用相同协议。

模型并非凭空记住上次状态：服务端/直连适配器保留实际 messages 和上次有效 assistant 结果，将增量作为下一条 user 消息送给 LLM。这样保留可缓存的稳定前缀，避免每次在新 user 消息里重传未变内容。原始 HTTP 更新包也不带未变正文。超过有限历史长度/字符预算时重新基于当前紧凑模型建立上下文；引用被淘汰时显式返回 409，客户端在同一个 10 秒预算内补发完整紧凑模型。这是传输缓存重建，不是本地方案兜底。不能据此声称总 token 为零；实际 provider 缓存命中需以供应方 usage 验证。

## 调度、复用和十秒上限

- 后台每 500ms 维护工作区，去抖和限频请求模型；不是每 tick 调用模型。稳定状态也按缓存有效期刷新，避免只有一次性预计算。
- 只使用真实、通过协议及能力校验的模型结果。没有本地候选生成器，没有固定三技术菜单。
- task/content、焦点、约束和对象集合须兼容；小幅几何变化可直接复用，执行时按当前快照重新编译。当前 5% 归一化布局容差属于可调整工程参数，不是实验收益阈值。内容、对象或明显几何变化需要模型更新。
- 实时请求优先；相同/兼容的在途计算合并，变化较大时抢占旧任务并发送增量。序号及取消信号隔离旧响应。
- 保留原 2.5 秒选窗手势；无结果时进入 waiting，不移动窗口。自显式触发起满 10 秒仍无可用结果，取消请求并显示 Error。进入 waiting 后松开空格仍等待真实结果；返回后显示预览并等待再次按空格采用，不能自动采用尚未看过的结果。Esc 始终允许主动取消。
- 所有候选均为模型结果。已有预览不会被后台响应突然替换；有效新模型建议可另行追加，用户自行选择。
- `[]` 是模型真实返回的空候选，与网络失败/协议错误区分；不把错误说成已经最优。
- 快速 LLM 请求使用受约束 JSON、有限候选及输出预算；关闭 thinking，避免在实时布局路径等待隐藏推理。共同协议使服务端和访客直连行为一致。

## 已启用与暂缓的能力

运行时接受 arrange、encapsulate、permeate，以及已存在的 fuse、corner-peel、region。融合和真实掀角复用手动交互的数据与几何；不新增交互技术。胶囊允许收纳单窗或多窗，但会隐藏正文，不能当作可见侧栏。

布局规范可指定横/纵方向、顺序、相对比例与主窗口。本地求解保证可读尺寸，不能求解的候选明确拒绝；不会全部套用两个固定模板。区域操作仅能引用用户已标记的区域；将保留区转为洞还须显式选中该窗口。禁止模型猜测正文坐标或生成区域。

plan.artifacts 必须为空；自动让界、生成内容的分生/汇合、裁剪边缘式揭示均不接受。任务默认未知工作区，应用名称不再自动决定论文/文件任务。只在实际来源支持时解释任务；允许同一场景得到同样建议，不设置多样性配额。

## 工程诊断

记录请求、实际模型候选 ID、协议/能力/几何拒绝原因、展示、缓存复用和采用。开发模式写入 log/YYYY-MM-DD/runtime.jsonl，也可用 window.__aw.agentDiagnostics.export() 导出本地环形记录。日志关联服务端 traceId；访客直连也记录相同的客户端过滤阶段。记录不含正文或密钥，不作为实验结果或用户收益权重。

旧模型会话的 system 提示词发生变化时，以当前紧凑状态重新建立上下文，避免旧的能力限制继续影响增量请求。

## 留给实验的接口

policy.ts 的 ExperimentalEvidence 返回带 studyId/version 的时间、错误率、恢复成本及不确定性。pendingEvidence 返回 null，RewardProvider 未配置；不填造权重，不从 LLM priority/confidence 推导实际用户效率。模型 priority 仅是远端建议顺序。verification.ts 计算的是窗口移动数量/距离、缩放数量和收纳数量，不声称是用户负担或认知收益。

个人偏好推断、稳定切换收益阈值、复杂技术组合的效用、跨场景泛化与 Agent 验证数据采集均保留，不在本轮假装完成。预览冻结已经阻止迟到响应造成的抖动，不等于实现 Adaptique 的性能阈值模型。

## 验证入口

- pnpm test：状态、协议、编译、抢占、语义失效、内容预算、解释证据与事务回归。
- pnpm test:agent-native：受控模型响应调用真实掀角、融合与区域操作，检查预览、采用、撤销及内容保留。
- pnpm test:agent-workspace：等待真实响应、十秒超时、真实缓存复用、显著变化的增量请求、显式采用和撤销。
- pnpm test:desktop / test:study：已有 AI 问答权限、真实应用接口、桌面与实验隔离等回归。
